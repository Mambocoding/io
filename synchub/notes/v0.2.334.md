## 0.2.334

owes: none — a requested accuracy range is clamped to the 400 days before yesterday even with no archived day, and the on-request accuracy cache is one shared store bounded at 256 entries across the weather sensor pages.

owes: none — a stocks *Refresh* leaves the portfolio's currency pairs to the fetch loop, one quote key is never dialled twice at once whether the loop or any owner's click asks, and a refresh banner's `error` in the address is drawn only as `http_` and three digits (stocks and weather).

owes: a changed default — a sign-in now sets a signed `synchub_known_device` cookie (HTTP-only, secure, the account's id and a signature, no secret), and an attempt arriving while the account is spaced out after a wrong one is verified only when it carries that cookie, otherwise answered `429` unchecked (SPEC-089 D42, REV-HUB-76). A browser that signed in before this release has no cookie until its next successful sign-in, and its owner waits out the delay if a guess just failed; a client without a cookie jar (the API) waits it out the same way. No migration, no key to set: the signing key derives from `integrity.key`, which a restore never carries, so a restored hub asks each browser to sign in once more.

owes: none — re-pinned SyncCore 0.10.51 → 0.10.54, DataCore 0.6.29 → 0.6.32 and Tooling 0.1.92 → 0.1.96 (none owes this hub anything); `PanelWidthBrowserTest` waits for the keys' own save (test only).

owes: SyncDesk at its next re-pin — `uiModel` 34 adds the stocks board's *Refresh* (SPEC-212): the `stocks.refresh` action, which the engine relays to `POST /api/v1/stocks/refresh`, and the board facts' `refresh`, `refreshError`, `refreshAtMillis` and `refreshDeferred`; an older reader shows no button and no banner. For an operator, a changed default: a click on the board's *Refresh* redials every quote the person follows that was last attempted at least a minute ago, whatever its interval or market state (at most 20 per source, about 20 s), where the API's refresh redialled only quotes past their interval or failed. The API answer gains `deferred` (absent reads as 0). No migration, key or wire collection changes, and a rollback loses only the button.
